# מפת מבנים מסוכנים — תל אביב, חולון ובת ים

**[פתיחת המפה באתר הציבורי](https://igor-mish.github.io/danger_map/)**

ממשק ווב בעברית עם חיפוש, סינון עיר, פרטי רשומה וקישור למסמך המקור. בת ים נכללת עם כל 205 רשומות ה־GIS, ללא סינון קוד סטטוס.

## הפעלה

```sh
cd /workspace/danger_map
npm ci
npm run dev
```

נדרשת גרסת Node.js הנתמכת ב־Vite 6: Node 18+ או 20+. הנתונים נשמרים בקובץ סטטי; אין שרת מסד נתונים, חשבון משתמש או דרישה למפתח API.

## הנתונים שהועלו

- תל אביב: 615 תיקים, מסמך מ־08.10.2026, כולל תיק אחד ללא כתובת במקור.
- חולון: 70 רשומות מבנים מסוכנים, מסמך מ־15.07.2026. ברשימת יולי נוספו והוסרו כתובות לעומת גרסת מאי.
- חולון: 17 מבני פל־קל בקטגוריה נפרדת, מוסתרת כברירת מחדל.

הספירה היא של רשומות ותיקים, לא מבנים ייחודיים. כמה תיקים עשויים להתייחס לאותה כתובת. קובצי המקור שהועלו זמינים תחת public/sources, וקובץ הנתונים public/data/buildings.json שומר מספרי תיקים, מספרי עמודים, תאריכי מקור וחתימות SHA-256. חילוץ תל אביב נבדק מול הסיכום המוצהר ב־PDF; חולון נבדקת לפי הרצף הממוספר. מיקום כתובת נקבע באמצעות OpenStreetMap ולא באמצעות העיריות. אין להסיק חומרת סכנה מצבע הסמן.

## בת ים — צילום GIS מ־14.10.2026

כל 205 הרשומות משכבת ArcGIS מספר 17 מוצגות, כולל 198 עם קוד סטטוס פ ו־7 עם קוד ל. המשמעות של הקודים לא הוגדרה במטא־דאטה ולא מוסקת באפליקציה. הרשומות כוללות 169 מספרי תיקים ו־145 כתובות ייחודיות; אין איחוד או מחיקה של רשומות שמופיעות באותה כתובת. מקור הנתונים הוא תשובות JSON מתוך HAR שסיפק המשתמש; הקובץ הציבורי public/sources/bat-yam.json מכיל נתונים ומזהים בלבד, ללא כותרות HTTP, עוגיות או פרטי הזדהות.

כל הרשומות מכילות נקודות ברשת ישראל EPSG:2039, שהומרו ל־WGS84 באמצעות pyproj עם always_xy. היבוא מאמת את שלמות רשימת המזהים, היעדר כפילויות OBJECTID, היעדר exceededTransferLimit, תחום הקואורדינטות והמרה הפוכה בסטייה קטנה מ־0.1 מטר. מספרי בתים/תיקים/גוש/חלקה, תאריכי ההכרזה וקודי הסטטוס נשמרים. תאריך הצילום אינו תאריך העדכון העירוני. סנכרון חי עדיין לא אומת ולא מתבצע אוטומטית; אין לטעון שהתוכן עדכני תמיד.

import_sources.py כולל את צילום בת ים בכל בנייה מחדש, שומר מיקומים קיימים לתל אביב/חולון ומחשב מחדש את מיקומי בת ים מן המקור העירוני. כדי לרענן את בת ים יש להחליף צילום מאומת של כל הרשומות והמזהים, ואז להריץ את היבוא והבדיקות. אין צורך בגאוקודינג לכתובות בת ים.

## מיקומים ועריכה

כתובת שלא הותאמה חד־משמעית נשארת ברשימה ללא סמן. אין שימוש בנקודת מרכז העיר כתחליף למיקום המבנה. ניתן לסמן מיקום ידנית על המפה ולאשר שמירה; סימונים כאלה מתויגים כידניים ונשמרים מקומית בדפדפן. אין אישור עירוני למיקום ידני. ניתן לייצא את הרשומות ל־CSV, כולל המיקומים והמידע על המקור.

טעינת CSV ידנית דורשת UTF-8 וכותרות city,address,lat,lng. עיר חייבת להיות תל אביב, חולון או בת ים. שדות נוספים שנשמרים: id, category, source_date, source_page, case_id, notes, geocode_label. category=pal-kal מציין קטגוריית פל־קל. קואורדינטות הן WGS84, lat ואז lng. נתוני CSV נשארים בזיכרון הדפדפן עד רענון; מיקומים ידניים נשמרים ב־localStorage ואינם משותפים למשתמשים אחרים.

## רענון ושחזור

```sh
cd /workspace/danger_map
.venv/bin/python -m pip install -r scripts/requirements.txt
# אופציונלי: הורדה חדשה מהעיריות; הקבצים המקוריים כבר נמצאים בסביבה
.venv/bin/python scripts/download_sources.py
.venv/bin/python scripts/import_sources.py
.venv/bin/python scripts/geocode.py
```

היבוא קורא תאריכים מתוך המסמכים ושומר מיקומים קיימים רק כאשר מזהה הרשומה והכתובת נשארו ללא שינוי. העתק את קובצי data/sources ל־public/sources לאחר בדיקת יבוא מוצלחת כדי להתאים את המסמך המוצג לנתונים. אין להריץ יבוא וגאוקודינג בו־זמנית.

גאוקודינג משתמש ב־Nominatim עם User-Agent מזהה, בקשות סדרתיות בהפרש של לפחות 1.1 שניות ומטמון מקומי. הוא בודק עיר, רחוב ומספר בית; תוצאות מרוחקות זו מזו, טווחי מספרי בתים וכתובות חסרות נשארים ללא מיקום. כמה מאפייני OSM באותה כתובת מתקבלים רק אם הם נמצאים במרחק של עד 35 מטר זה מזה. תוצאות אוטומטיות אינן מדידה מוסמכת. שגיאות רשת והרשאות עוצרות את התהליך ושומרות את ההתקדמות; ניתן להריץ שוב. אין להריץ כמה תהליכי גאוקודינג במקביל.

## בדיקות

```sh
cd /workspace/danger_map
npm test
npm run build
# כאשר שרת הפיתוח פועל
npm run test:browser
cd /workspace/danger_map
.venv/bin/python -m unittest discover -s danger-map/scripts -p 'test_*.py'
```

בדיקת הדפדפן משתמשת ב־Chromium המותקן במערכת, או בדפדפן Playwright. אפשר להגדיר CHROMIUM_PATH ו־APP_URL. כאשר קיים HTTPS_PROXY, הבדיקה מעבירה תגובות מפות וגופנים אמיתיות דרך לקוח HTTPS שסומך על תעודת הפלטפורמה; אימות TLS נשאר פעיל. לא מוחזרים אריחים מדומים. בדיקות CSV משתמשות בכתובות דמה רק בהקשר דפדפן זמני ואינן משנות את הנתונים שבמאגר.

## מפות ורשת

אריחי המפה: OpenStreetMap, עם ייחוס וקישורי זכויות. גאוקודינג: Nominatim; נתוני OSM כפופים ל־ODbL. השימוש באריחים כפוף למדיניות https://operations.osmfoundation.org/policies/tiles/ והשימוש בגאוקודינג למדיניות https://operations.osmfoundation.org/policies/nominatim/. סביבת ייצור עם תעבורה משמעותית דורשת ספק אריחים מתאים. גופני Google אופציונליים וקיים גופן חלופי מקומי.

לסביבת הפיתוח נדרשת גישה ל־nominatim.openstreetmap.org, a.tile.openstreetmap.org, b.tile.openstreetmap.org, c.tile.openstreetmap.org. לרענון המקורות: www.tel-aviv.gov.il ו־www.holon.muni.il. לגופנים: fonts.googleapis.com ו־fonts.gstatic.com.

`npm run build` מפיק את dist לאירוח סטטי. האתר פורסם ב־GitHub Pages ונבדק בכתובת הציבורית. גרסת האתר הבנויה נשמרת בענף gh-pages. הסטטוס ברשימות עשוי להשתנות מאז תאריך המסמך; בדיקה עדכנית נעשית מול הרשות המקומית.

## פרטי מבנה

בבחירת מבנה בתל אביב מוצגים מספר התיק, מצב אכלוס, מצב טיפול, סעיף הצו, תאריך פתיחת התיק, ביקור אחרון, תאריך מצב הטיפול וסימון מבנה שמור כפי שמופיע במקור. בבת ים מופיעים קוד הסטטוס המקורי, תאריך הכרזה, גוש/חלקה וקישור לתיק הפיקוח. הקישורים נפתחים בלשונית נפרדת. אין פירוש של קודי הסטטוס פ/ל.

בחולון כל 70 רשומות המבנים המסוכנים זמינות ברשימה, אך 13 מוקמו אוטומטית ברמת מספר הבית; 57 רשומות נשארות ללא מיקום. בנוסף יש 17 רשומות פל־קל, מהן 7 מוקמו, בקטגוריה נפרדת. ספירת הכיסוי מוצגת לצד המסננים; אין סימון במרכז הרחוב במקום מיקום מבנה.

לרענון מיקומי חולון בלבד: `.venv/bin/python scripts/geocode.py --city חולון`. היבוא משמר מיקומים קודמים של חולון לפי שילוב קטגוריה, כתובת, גוש וחלקה, ולא לפי מספר השורה ברשימה, שעשוי להשתנות בין גרסאות. שירות ה־GIS של חולון כולל שכבות גושים וחלקות, אך שליפת הגאומטריה דרך הפרוקסי מחזירה שגיאת שרת ולא אומתה; מיקומי חלקות לא הומצאו ולא הוצגו כמיקומי מבנים.

וולפסון 26 בחולון מוצג לפי מיקום חלקה 196 בגוש 6021, מתוך קישור GovMap וצילום מסך שסיפק המשתמש. סמן כחול ותווית מבהירים שמדובר במיקום החלקה ולא במיקום מדויק של מבנה או כניסה. המיקום נשמר ביבוא מחדש לפי כתובת, גוש וחלקה יחד, בקובץ public/sources/holon-parcel-locations.json. כיום לחולון יש 14 רשומות עם מיקום: 13 התאמות כתובת ומיקום חלקה אחד. 56 רשומות נותרו ללא מיקום. שאילתות GovMap אוטומטיות לא הוגדרו; התיעוד הרשמי דורש מפתח API ודומיין מאושר.

## תל אביב — השלמה משכבת GIS עירונית

צילום ה־HAR של המשתמש מ־14.10.2026 מכיל 607 רשומות משכבה 591 של שירות WM/IView2WM. הבקשה ב־HAR סיננה ms_bayit > 0. לאחר מכן אומת מול ה־API החי ש־where=1=1 מחזיר גם הוא 607 רשומות, וכל המזהים תואמים; נשמרה שליפה חיה מלאה שנבדקה. תאריך הטעינה בשכבה הוא 11.10.2026, ואינו בהכרח תאריך העדכון של כל תיק. צילום הנתונים הציבורי בלבד, ללא כותרות/עוגיות מה־HAR, נמצא ב־public/sources/tel-aviv-gis.json.

היבוא משווה כתובת מדויקת: שם רחוב מנורמל, מספר בית וכניסה. כל הנקודות מומרות מ־EPSG:3857 ל־WGS84 ונבדקות מול תחום העיר. כשיש כמה תוצאות, הן מתקבלות למיקום רק אם המרחק המרבי ביניהן עד 5 מטר; אחרת לא נבחרת נקודה אוטומטית. 586 תיקים מה־PDF קיבלו מיקום עירוני, ובשילוב 23 מיקומים קודמים יש 609 רשומות תל אביב עם מיקום מתוך 615.

פרטי התיק, מצב האכלוס והטיפול ממשיכים להגיע מה־PDF. תיאורי הצווים והממצאים בשכבת GIS מוצגים ישירות באותו כרטיס, תחת ״ממצאים ותיאור צו״, ללא טענה שהם משויכים לתיק PDF מסוים: בשכבה אין מספר תיק תואם. טקסט הממצאים מוצג כפי שפורסם (עד 254 תווים בצילום הזה), ולא מושלם באופן משוער. רשומות GIS שאין להן התאמה לכתובת PDF אינן נוספות כתיקים חדשים לרשימה; כולן נגישות בקובץ צילום השכבה. סנכרון חי עדיין לא הוגדר.

רענון שכבת תל אביב ללא HAR: `.venv/bin/python scripts/refresh_tel_aviv_gis.py`, ולאחריו `.venv/bin/python scripts/import_sources.py`. פקודת הרענון משתמשת ב־API הציבורי, שולפת את כלל המזהים ואז רשומות בקבוצות, בודקת שהמזהים לא השתנו במהלך השליפה, ומחליפה את צילום המקור רק לאחר אימות מלא. אין צורך במפתח GovMap. לאחר הרענון נדרשים בדיקה, בנייה ופרסום מחדש; אין עדיין תזמון אוטומטי או עדכון אוטומטי של ה־PDF.

## חולון — מיקומי כתובות B144

כל 70 רשומות המבנים המסוכנים ו־17 רשומות פל־קל כוללות מיקום. צילום `public/sources/holon-b144.json` נבנה מתשובות שהמשתמש שלף ב־B144 ומהתיקונים שסיפק בשיחה. המקור אינו אישור עירוני או אימות מול חלקה. הכתובות והגושים/חלקות נשארים כפי שב־PDF; סיומות/כניסות אינן נדרשות לאיתור לפי הנחיית המשתמש. כיכר וייצמן אותרה באיות עם שתי יו״דים, ולא בתוצאות השגויות של דן שומרון. ראש פינה 1+3 מוצגת בשני סמנים, וההסתדרות 94,96,98,100,102 בחמישה, תוך שמירת רשומת המקור היחידה. לכן יש 75 סמנים ל־70 רשומות מבנים מסוכנים בחולון.

וולפסון 26 שומר על מיקום החלקה הקודם מ־GovMap. יתר מיקומי חולון משתמשים ב־B144 עם תווית מקור ורמת דיוק כתובת. בשלוש רשומות בעל שם טוב יש פער לעומת Nominatim הקודם והוא מצוין בתווית; החניון באילת 36 לא אותר בנפרד מכתובת הבסיס. היבוא מחיל את צילום B144 אחרי נתוני ה־PDF ומיקומי החלקות, ומוודא התאמה לפי קטגוריה, כתובת, גוש וחלקה. לא מתבצעות בקשות B144 בעת פתיחת האתר.

## חיפוש כתובת וסביבה

״חיפוש כתובת במפה״ משתמש ב־Nominatim הציבורי לאחר לחיצה מפורשת בלבד, ללא השלמה אוטומטית. העיר המסוננת מצורפת לחיפוש כשלא נכתבה עיר. בחירת תוצאה מסמנת את מיקום החיפוש בכחול ומציגה מבנים ברדיוס 500 מטר בקו אווירי; ניתן לבחור 250, 500, 1,000 או 2,000 מטר. מסנני העיר ופל־קל נשמרים, וסינון הטקסט של הרשומות מתנקה בבחירת הכתובת. ״ניקוי מיקום החיפוש״ מחזיר את הרשומות לפי המסננים. רשומות ללא מיקום אינן נכללות בחיפוש מרחק. איכות האיתור תלויה בכיסוי OSM; תוצאת רחוב ללא מספר בית מסומנת בהתאם. הסמן הכחול אינו קביעה שהכתובת מסוכנת או בטוחה. תוצאות החיפוש נשמרות בזיכרון הדף, ובין בקשות חדשות יש הגבלת תדירות מקומית. אין מפתח סודי בקוד הדפדפן.
